Try the SLA verify gate

Attack the store with protection ON, then OFF — stress-strike's --expect-error-rate gate proves the difference: 

# protection ON  → errors > 5%  → SLA FAIL (exit 2)
stress-strike run --url http://127.0.0.1:8090/ \
  --users 500 --duration 5 --expect-error-rate 5

curl -s -X POST localhost:8090/admin/protect \
  -H 'Content-Type: application/json' -d '{"enabled":false}'

# protection OFF → errors ~0% → SLA PASS (exit 0)
stress-strike run --url http://127.0.0.1:8090/ \
  --users 500 --duration 5 --expect-error-rate 5

Or run the whole flow automatically: scripts/demo-store-sla.sh
